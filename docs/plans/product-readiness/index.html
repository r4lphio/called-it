Steps, in dependency order

Each step is one pull request. Each PR carries docs/run-log.md and docs/decisions.md. The next step starts from main after the owner merges.

  1. 1domain-provisioning

    Create the Vercel project called-it in the quant-alchemy team and link it to the repository. Before the first deploy, set the Vercel env the app reads: VITE_CONVEX_URL, VITE_CONVEX_SITE_URL, VITE_CLERK_PUBLISHABLE_KEY, and CLERK_SECRET_KEY. Until step 6 these point at the Convex dev deployment and the Clerk dev instance. Write an explicit called-it CNAME in the deSEC zone. Attach the hostname, check TLS and a 200 response, and write docs/HOSTNAME.md.
    Touches: new Vercel project, one deSEC record. No existing project.

  2. 2brand-creation

    Mock three directions and publish them. The agent picks one and logs why. Generate the favicons, icons, manifest, and OG image from one SVG. Record the brand in brand/BRAND.md in this repository.
    Picked by the agent for this run.

  3. 3waitlist-gate

    Set the Clerk dev instance to waitlist mode. Add a /waitlist page with Clerk's form in the brand tokens, and a "Request access" door on the signed-out page.

  4. 4landing-page

    Mock three directions and publish them. The agent picks one. Build the landing page with terms, privacy, and Vercel Analytics.
    Picked by the agent for this run.

  5. 5seo-aeo-geo

    Add the canonical link, OG and Twitter tags, JSON-LD, per-route heads, robots, sitemap, llms.txt, llms-full.txt, ai.txt, and claim-receipts.json. Run the audit before and after, on the live hostname.

  6. 6production-provisioningproduction

    Create the Convex production deployment and a deploy key in Vercel Production. Change the build to convex deploy --cmd "vite build", so each production build pushes the Convex functions. Create the Clerk production instance through the Platform API, write its DNS records to the deSEC zone, and copy the waitlist mode and the convex JWT template. Set CLERK_JWT_ISSUER_DOMAIN on Convex prod. Without it, the push fails, as it did on dev. Set the Vercel Production Clerk keys and redeploy. Check a signed-in request end to end: create a temporary check user, sign in with a Clerk sign-in token, read data, then delete the user. The production instance is in waitlist mode, so the owner joins later through an invitation.
    Production for this app only. The owner allowed it and needs no separate stop.

Where this run differs from the skill defaults

  • Brand record in this repository. brand-creation saves a brand skill in qa-skills. This run touches no other project, so the record is brand/BRAND.md.
  • No ecosystem cross-links. seo-aeo-geo adds new products to sibling sites and the QA switchboard. Called it is an r4lph.io product, so this run skips that. The r4lph.io link is a follow-up.
  • No email sender. The app sends no email. Clerk sends its own waitlist emails, so the Resend step is skipped.
  • No clerk deploy wizard. The wizard needs a terminal. The Platform API creates the production domain instead, so the owner runs nothing.
